## 一、项目定位

**AI 康养旅居智能规划平台** — 不是普通旅游网站，也不是 Three.js 技术演示。

核心公式：

**AI + GIS + 康养决策体验**

用户从空间探索开始，逐步形成"这个地方是否适合我"的判断。图片和生活故事建立向往，可信环境数据、医疗与预算信息辅助决策。

### 当前阶段核心矛盾（2026-08-12）

UI 设计已有多样化呈现，但**功能深度不足，缺乏数据支撑**是当前产品的主要瓶颈。
即日起 UI 设计暂停，重点转向功能打磨与数据体系建设。

---

## 二、产品理念

1. **空间探索 → 形成判断**：用户不是来"看地球动画"的，是来理解"在这里生活会是什么样"的。
2. **故事 + 数据双驱动**：图片与生活故事负责建立向往，可信环境/医疗/预算数据负责辅助决策。
3. **数据解释优先**：不直接暴露数据库字段，始终以用户能理解的语言解释数据含义。
4. **AI 辅助 → AI 全权决策**：用户可以选择让 AI 辅助判断，也可以全权交给 AI 决策。

---

## 三、设计原则

### 保持

- Apple 产品级的清晰层级、留白和交互克制
- Apple Vision Pro 式空间层次，但空间效果必须服务叙事
- Google Earth 式真实位置感
- National Geographic 式图片与故事驱动
- 自然高级感、深海蓝绿、晨昏自然光和暖白文字
- 真实摄影、可追溯来源和明确许可
- 自动探索优先，自由探索辅助

### 避免

- 为了 3D 而 3D
- 黑色科技 Demo 感
- Portal、扫描圈、夸张光环和无意义漂浮按钮
- 普通后台数据卡和技术化文案
- 未核验的旅游故事、医疗效果或无关图片

## 四、功能方向

> 细致路线见 `docs/开发日志.md`，此处仅列高层方向。

### 数据体系建设

- 问卷指标体系需要数据支撑，可参考现有苏马荡 IPA 分析的问卷指标
- 所有功能判断应有可信数据源，而非纯前端体验
- 康养路线、附近推荐和节点位置必须基于真实 GIS/POI 数据，不允许由 AI 凭记忆生成。
- 国内目的地优先评估高德地图 Web 服务作为 POI 检索、地理编码和道路路径规划的数据来源；前端 OpenLayers 负责地图表达与编辑，高德 Web 服务密钥和请求代理放在后端。
- 高德 POI 数据不能自动等同于可信价格、医疗能力或康养适配结论：价格需结合商家或授权来源并记录观察时间，医疗能力优先采用政府和医院官方来源，AI 仅负责解释和编排。
- 所有外部地图数据必须记录供应商、原始 ID、坐标系、采集时间、核验状态和许可边界；正式接入前重新核对高德开放平台当期配额、接口规则与数据使用条款。

### 地图与路线规划（核心功能）

- 用户可直接在二维和三维地图上标注旅游路线和规划
- 路线规划时，自动推荐附近民宿、景点、餐馆等
- AI 可辅助路线决策，也可全权交由 AI 规划

### AI 决策能力

- AI 辅助模式：建议式推荐，用户最终决定
- AI 全权决策模式：用户设定偏好和约束，AI 直接输出完整方案
- 这是产品长期差异化的核心能力

### 亮点功能

- 持续补充值得按次消费的实用功能（以建议形式补充，不堆砌）
- 亮点功能必须有数据支撑，不能是纯视觉卖点

## 五、产品架构

### Act1：首页品牌入口（已完成）

品牌主视觉和产品定位，"开始探索"进入 Act2。

### Act2：AI 康养旅居数字探索（已完成收口）

Three.js 数字地球、12 个目的地点位、自动探索 → 故事面板 → 定向问卷 → 适合度结果闭环。
用户第一次进入后，即使不操作鼠标，也能完成一次首站探索。

数据入口统一使用 `window.HealthTravelAPI.getDestinations()`：
- `/api/destinations` 优先
- `destinations.geojson` fallback
- `destination-content.json` 合并故事与图片
- API 与内容清单 ID 不一致时，必须验证名称后再合并
- 不得把故事、图片重新硬编码到 EarthEngine 或 UI

### Act3：目的地深度体验（12 目的地内容结构已接入）

用户感受应是"我正在理解在这里生活会是什么样"，不是"我又进入了一个动画页面"。
第一版以大理为完整样板。

### Act5：康养线路工作台（当前）

M5/M6 已完成大理二维手动路线和 AI 引导规划；M7 已增加统一 POI 查询、来源/有效期状态和独立价格快照契约；M8 已让 OpenLayers 和 Three.js 读取同一份路线模型；M9 已增加带访问令牌、乐观版本控制和历史归档的路线持久化。地图供应商只证明位置与道路，价格、医疗能力和康养适配必须使用各自可追溯来源。没有授权价格时必须保持空值，不能为了界面完整而推测金额。

当前三维只表达真实水平空间关系；没有真实高程数据时不得生成坡度结论。路线属于含健康偏好的私有数据：不得新增公开列表，不得记录明文访问令牌，不得在冲突时静默覆盖。M10 使用 SQLite FTS5 + Qdrant + BGE 中文向量，只检索有授权、可追溯且未过期的长文证据，不替代结构化事实、GIS 路线或价格快照。当前 26 份文档、55 分块覆盖 12 个目的地；覆盖代表最小可查证，不代表实时数据完整。Act3 与结果页的证据追问固定本地执行；无证据必须拒答，外部 AI 必须明示授权，引用校验失败必须降级。

### Act4：AI 康养决策中心（基础链路已存在）

通用 questionnaire/results 流程可用，后续随 Act3 深化。
